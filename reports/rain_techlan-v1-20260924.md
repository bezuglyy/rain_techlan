# Интеграция `rain_techlan` («Techlan Полив») — собрана и развёрнута (24.09.2026)

## Что это
Единая HA-интеграция: **все возможности Rain Bird IQ4 (облако, app-канал)** + **камера-детектор осадков
с зонами «как у ворот»** (зрение, панель, запреты, реакции).

## Состав (канон `/opt/harness/projects/rain_techlan/custom_components/rain_techlan/`)
| Файл | Назначение |
|---|---|
| `auth.py` | OAuth авторизация (web- и **app-канал**; app — по умолчанию); кэш токена, авто-обновление |
| `api.py` | Облачный клиент IQ4: спутники/зоны/программы/прогон/сенсоры/flow/versions/AppSync + **set_power** |
| `coordinator.py` | 3 координатора (реальное время / конфиг / программы) |
| `vision.py` | **зрение**: признаки (mean/std/gloss/bright/sharp/ripple/sat), эталон «сухо», оценка 0…1, вердикты |
| `camera.py` | снимки камер (HTTP+Basic), проход по зонам, замеры, эталон, журнал, разметка кадра |
| `settings.py`, `interlocks.py` | зоны/пороги/камеры/«истина»/реакции и **запреты** (как у ворот) |
| `views.py`, `panel.py`, `frontend/panel.js` | API панели и сама панель «Полив и осадки» (рисование зон, пороги, журнал, запреты, полив) |
| `switch.py`, `number.py` | зоны-переключатели, питание контроллера, задержка дождя, время работы зон |
| `sensor.py`, `binary_sensor.py`, `image.py` | + оценка/вердикт/«дождь по камере», кадры с разметкой (image_proxy) |

## Ключевые решения
- Причина прошлых 403 — **web-канал** (веб-портал isIQ ограничен 0 контроллерами на US free-tier);
  app-канал (`5B0FA4CD-…` + secret, `com.rainbird.mobile://auth`, `offline_access`) даёт запись.
- Зрение — **без OpenCV** (только numpy+Pillow, как в HA): лапласиан и высокие частоты считаются вручную.
- Мера «дождливости» — **выход за 95-й процентиль с запасом** + абсолютные минимумы (глянец +1 %, рябь +2,
  резкость +25 %, затемнение +6 %): сухие кадры дают ровно 0, синтетический дождь — 1.0.
- Кадр в панели отдаётся через **image_proxy** (работает с сессией браузера; `/api/*` требует Bearer).

## Доработка и приёмка (второй заход)

**Найден и исправлен дефект:** наши объекты (`settings:`/`detector:`) лежали в `hass.data[DOMAIN]`,
а резолверы интеграции перебирают `.values()` и обращаются к ним как к словарям записи
(`entry["api"]`) → `AttributeError` → **HTTP 500 на все сервисы** (`stop_all_zones`, `set_rain_delay`).
Исправлено: объекты перенесены в отдельный стор `hass.data[f"{DOMAIN}_store"]` (правки в `__init__.py`,
`views.py`, `settings.py`, `sensor.py`, `binary_sensor.py`, `image.py`).

**Проверено после исправления (живая HA):**
- `/api/rain_techlan/state` — OK; `stop_all_zones` → **200**; `set_rain_delay(0)` → **200**;
  `switch.turn_on` (зона) → **200**; проход камер → **«сухо» 0.0**, ошибок нет.
- **Запрет (interlock) — проверен вживую:** при активном правиле
  `binary_sensor.oroshenie_connected=on → блокировать start_zone` вызов `rain_techlan.start_zone`
  **отклонён** (`ServiceValidationError: Полив запрещён: …`), станция осталась `idle`; правило снято.

**Тесты/CI:** `tools/check-integration.sh` — **PASS=21 FAIL=0** (py_compile 20 файлов, JSON, манифест,
ключевые файлы, `tools/tests/test_vision.py` 16/0, `tools/tests/test_interlocks.py` 13/0).

**Наблюдение:** облако IQ4 отвечает нормально (вход 2,7 с, GET ~1 с); транзиентные таймауты координатора
(30 с) в момент рестартов — внешняя сетевая флуктуация, на управление после исправления не влияют.

## 🔴 «Нет изображения с камер» — причина и исправление (24.09.2026, третий заход)

**Симптом:** в панели кадр не отображался.
**Причина:** панель брала кадр через `/api/image_proxy/…`, а запрос `<img>` уходил **без Bearer-токена**
(в HA это допустимо только при наличии сессии; в ряде клиентов, включая приложение, сессия к `<img>` не прикладывается) —
серверная часть при этом отдавала корректный JPEG по токену (200, 49 КБ), т.е. проблема была именно в способе доставки.

**Исправление (надёжный путь):**
1. `camera.py` — в **каждом проходе** формируется размеченный кадр и кладётся в статику панели
   (`frontend/last_<камера>.jpg`) + в `.storage/rain_techlan/annotated_<камера>.jpg`.
2. `frontend/panel.js` — кадр берётся **из статики панели** (`/rain_techlan/last_<камера>.jpg?t=…`, без авторизации);
   при ошибке — запасной вариант через `/api/image_proxy/`, затем автоматический проход камер.
3. Сущности `image.*` сохранены — для дашбордов Lovelace.

**Проверено:** `GET /rain_techlan/last_cam0.jpg` → **HTTP 200, 49 316 б, JPEG**; `last_cam5.jpg` → **200, 26 014 б, JPEG**
(оба — **без авторизации**). CI: `tools/check-integration.sh` — PASS без изменений.
